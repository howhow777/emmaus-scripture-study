# 經文搜尋與覆蓋查核

日期：2026-10-18。狀態：修訂已上獨立預覽；Android與iPhone已由使用者回報測試通過；最終版本的完整模型重測待完成。正式站未更新。

預覽：[互動圖譜](https://emmaus-preview.promelink.link/graph.html) · [逐卷查核](https://emmaus-preview.promelink.link/coverage.html)

## 問題的原因

1. **研究資料漏收，並非只少一個同義詞。** 原 E007 的新約引用是彼前3章，沒有太24:37–39或路17:26–27。文字搜尋與模型都只能選既有引用，模型的白名單不能回傳未收錄的段落。因此即使模型知道耶穌提過挪亞，也不能把缺少的經文送到圖譜。
2. **舊測試只能保證現有清單內部一致。** 檢查186組及既有連結，無法發現清單外應收而未收的平行經文。這是需要整體補強的驗證缺口。
3. **來源解析有共通缺陷。** 固定譯本有合排節號與只含異文註的節，不能把空字串當作經文不存在。此次明示合排節號、覆蓋節數及異文註；不自行拆句或補造正文。27卷新約發現6組合排及11處僅列異文註的節。
4. **搜尋與介面存在一般性問題。** 舊拼字與常見書名別稱缺乏統一處理；研究以外的站內引用未一致套用書卷、兩約及語者條件；有些被篩選隱藏的經文沒有恢復提示。這些皆已修正。模型服務失敗、索引版本不符與真正的空結果，現在也分別驗證。

文字搜尋仍是正規化後的字串比對。例如「挪亞」可能命中「瑪挪亞」；結果會顯示原文片段，這不等同於判定兩人相同。語意搜尋另核對人物、語者及動作；三個挪亞案例要求實際福音書段落進入前五名。

本次沒有證據可推論整個程式所有部分都失效。已辨認的是資料收錄缺口，以及解析、篩選與測試方法中可重現的共通問題。

## 查核範圍與資料

範圍維持耶穌相關的舊約引用、人物事件比較、身分、降生、甘願捨己救贖、復活及應許見證，不改成全本聖經搜尋。

- 固定來源的27卷新約、260章、7,957個節號均掃描，逐卷確認章節連續及SHA-256。
- 以引文／人物／稱號／律法語詞，以及譯本來源的舊約交叉註，產生獨立於原研究清單的1,220個候選；其中273個帶有來源交叉註。
- 497個候選已有研究引用，318個納入範圍內補充引用，405個附理由排除，待審0。候選的節數與引用段落的組數是不同單位。
- 這是可重現的候選調查，不是宣稱所有學界有爭議或沒有明示引文的互文均已窮盡。
- 原186組、原ID、原說明／界線、原有引用、原49組核心及原語者標註均由基準快照逐欄核對保留。
- 新增20組E187–E206；29組原研究補入57處平行／相關引用。新增項目包括挪亞、羅得、陳設餅、亞伯拉罕的日子、律法引文等，逐組列出解釋界線。
- 另有148處範圍內的補充引用；不因此建立新圖譜實線。包含受審敘事、誡命引用及應許的上下文。
- 最終索引共901個不同引用範圍，其中680個屬圖譜研究引用、221個為其他站內引用。段落內共有4,188筆經節文字記錄；重疊引用會重複記錄，不能稱為4,188個互不重複經節。
- 耶穌發言的正向標註目前149筆「條目—引用」，涵蓋84組研究。律法師、作者旁白、天上的聲音與耶穌的發言仍分開。

逐項理由、來源修訂與原文：[coverage-manifest.json](../data/coverage-manifest.json)。新增資料帳本：[research-additions.json](../data/research-additions.json)。

新增年代沿用已列來源的書卷／段落政策；背景與成書分開。提後2:8另保留傳統年代與較晚成書說的分歧，可查[美國天主教主教團的提後導論](https://bible.usccb.org/bible/2timothy/0)及其轉介的[教牧書信導論](https://bible.usccb.org/bible/1timothy/0)。年代不是精確年表。

## 模型兩輪驗收的狀態

第一個擴充索引 `ee126824683503ca2ef7` 曾完成24案例×2輪，共48次未快取的真實模型呼叫。recall@10為100%，precision為98.35%；兩輪的8個無關查詢均空結果，三個挪亞問題的必要段落均進前五。評分依預先凍結的案例及相關引用範圍，不在看到答案後放寬標準。原始紀錄保留於[前一索引驗證](diagnostics/semantic-live-before-final-corpus.json)。初期一個中斷且索引已過期的嘗試另列診斷，不計入48次成績。

後續的來源交叉註調查又補收耶穌直接引用誡命等段落，最終索引改為 **`4dce84e4f5eb107fa141`**。前述48次成績**不能代替最終索引驗收**。最終索引目前只通過上表的一個真實HTTPS冒煙案例，完整48次重測待執行。

現行服務的每日100次未快取呼叫是站主設定的保護措施，不代表已確認Codex訂閱耗盡。現有計數不足以完整再跑48次；依計畫停止條件，已請使用者選擇額外最多48次的獨立內部驗證，或維持額度分日完成。尚未獲答覆前，不繞過保護。公開服務的100次限制沒有提高。

完成門檻仍為：recall@10 ≥95%、precision ≥90%、三個挪亞問題每輪必要段落前五、無關問題空結果，並且所有案例使用真正模型、略過快取、無漏跑或隱藏失敗。

## 重跑方法

```sh
# 首次需取得來源；之後可離線核對
python3 scripts/build-scripture-previews.py --fetch
python3 scripts/build-coverage.py --fetch
npm run build:data
npm run build:coverage
npm run build:previews
npm run build:graph
npm test
npm run check:graph

# 需已安裝Playwright與Chrome；不呼叫模型，錯誤案例採注入
python3 scripts/verify-browser.py --site https://emmaus-preview.promelink.link

# 需先確認本次額度；會實際呼叫模型48次
python3 server/search_service.py --runtime /path/to/private-review-runtime --build .
python3 scripts/verify-semantic-live.py --runtime /path/to/private-review-runtime --rounds 2 --output reports/semantic-live.json
```

若使用`--resume`，僅能接續相同corpus的既有紀錄；任何服務錯誤會停止並保留失敗，不能刪除失敗後宣稱全數成功。前端與服務corpus不符時須顯示更新訊息，不回退成查無經文。
